# Петух и чекушки

Браузерная игра с мультиплеером на Node.js и Socket.IO.

## Что есть в проекте

| Файл | Назначение |
| --- | --- |
| `index.html` | Разметка игры и клиент Socket.IO (~28 КБ). |
| `css/` | Стили интерфейса, вкладки настроек и `hd.css` — тема для HD-графики. |
| `js/game.mjs` | Ядро игры (~2,3 МБ): графика, звук, геймплей, сеть. Загружается как ES-модуль. |
| `js/core/assets.mjs` | Манифест аудиоресурсов (`TRACKS`, `SMP_SRC`). |
| `js/core/postfx.mjs` | Пост-обработка кадра: свечение, виньетка, зерно, пылинки. |
| `js/core/settings.mjs` | Настройки графики и вкладки панели (явный API `createSettings`). |
| `assets/` | 41 медиафайл: спрайты, иконки и аудиодорожки. |
| `server.js` | HTTP-сервер: отдаёт игру, `/socket.io/socket.io.js` и `/health`. |
| `src/GameServer.js` | Игровой сервер: лобби, чат, синхронизация игроков и совместные режимы. |
| `src/config.js` | Настройки через переменные окружения. |
| `src/util.js` | Валидация и ограничение входящих данных. |
| `test/protocol.test.js` | Интеграционные тесты протокола (6 сценариев). |

## Быстрый старт

Нужна Node.js **20+**.

```bash
npm install
npm start
```

Откройте <http://localhost:3000>. Прямо из файла (`file://`) игра тоже запустится,
но мультиплеер будет выключен — сервер нужен, чтобы отдать клиент Socket.IO.

Термины:

```bash
npm run dev   # перезапуск при изменении server.js / src/*
npm test      # интеграционные тесты (поднимают свой сервер на свободном порту)
curl http://localhost:3000/health
```

## Переменные окружения

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `PORT` | `3000` | Порт HTTP-сервера (Render подставляет свой). |
| `HOST` | `0.0.0.0` | Адрес прослушивания. |
| `MAX_CONNECTIONS` | `400` | Лимит одновременных подключений. |
| `MAX_ROOMS` | `150` | Лимит лобби. |
| `MAX_ROOM_SIZE` | `15` | Максимум игроков в лобби. |
| `TICK_MS` | `100` | Частота рассылки позиций (10 раз/с). |
| `TRIP_WAIT`, `RITUAL_WAIT` | `20` | Длительность рейса и обряда в секундах. |
| `CLIENT_ORIGIN` | — | Разрешённый origin для CORS, через запятую. |

## Деплой на Render

1. Залейте в репозиторий **всю папку** (не только `index.html`).
2. Render → **New** → **Web Service** → подключите репозиторий.
3. Настройки:
   - **Runtime:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Health Check Path:** `/health`
4. Добавьте `PORT` задавать не нужно — Render сделает это сам. При желании задайте
   `MAX_CONNECTIONS` и `MAX_ROOMS` под свой план.
5. После деплоя проверьте `https://<ваш-сервис>.onrender.com/health`.

`render.yaml` в корне — альтернатива для деплоя через Blueprint (Render сам прочитает его).

> Бесплатный план Render засыпает без активности. Клиент это уже умеет переживать:
> при переподключении `join` по сохранённому `uid` возвращает игрока в его лобби,
> если оно ещё существует.

## Настройки и графика

- **HD-графика включена по умолчанию.** Старые сохранения с лёгким режимом один раз переводятся в HD; в главном меню есть переключатель.
- В настройках — вкладки **Графика / Звук / Игра / Сеть / Прочее** вместо длинного скролла.
- Пресеты графики: **Экономия** (лёгкий режим, пониженная чёткость, без эффектов), **Качество** (HD, свечение и виньетка), **Максимум** (полная чёткость, зерно, все эффекты).
- Дополнительные опции: виньетка, мягкое свечение, зерно плёнки, количество частиц, тряска экрана, анимации интерфейса, FPS и пинг. Всё сохраняется в `localStorage`.
- Пост-обработка кадра (свечение, виньетка, зерно, лётящие пылинки) рисуется поверх сцены в `drawPostFx()`.
- Экран «Важное объявление автора» удалён из клиента.
- Автоподбор чекушек теперь включён по умолчанию (старые сохранения мигрируют один раз): просто проходи мимо чекушки, чтобы поднять её. Ручной подбор всё ещё работает кнопкой E.
- Клиент разбит на ES-модули: ядро плюс отдельные модули ресурсов, пост-эффектов и настроек. Из-за `type="module"` игра требует запуска через сервер (`npm start`).

## Протокол (для разработчиков)

Клиент шлёт → сервер отвечает:

| Событие клиента | Ответ сервера |
| --- | --- |
| `join {n,s,a,fm,u}` | `nick {ok,w,n}` при занятом нике, `room`, `lobbies` |
| `create {max}` / `enter {c}` / `leave` | `room` (объект лобби или `null`), `lobbies`, `left` |
| `lobbies` | `lobbies [{name,host,c,n,max}]` — ещё и ping-эхо клиента |
| `state {...}` (20 Гц, volatile) | `players [{id,n,s,a,x,z,l,...}]` (10 Гц) |
| `chat {t}` | `chat {id,n,t}` |
| `boss {...}` | `boss {start\|deny\|own\|sn\|dmg\|atk\|blind\|end}` |
| `kr {...}` | `kr {start\|deny\|own\|sn\|dmg\|end}` |
| `flight {start\|board\|unboard\|cancel}` | `flight {st:'wait',by,n,left,b,t}` → `{go,ids}` |
| `rit {start}` | `rit {st:'wait'}` → `{go,ids,alt}` (в круге: `l=13, rc=1`) |
| `uni {k,kind,l}` | `uni {ids,k,kind}` — составляет группу до 4 игроков |
| `story {...}` | `story {...}` — ретрансляция внутри группы: гости → хост, хост → гости |
| `rv {to,f,gh,x}` | `rv {n,f,gh,x}` — воскрешение адресату |
| `rb {b\|go}`, `mkt {id}` | рассылка по лобби |

Сервер не доверяет клиенту: ник и чат нормализуются, позиции и числа ограничиваются,
события сюжета проходят проверку структуры и размера, на каждое событие есть
ограничение частоты. Всё, что не относится к этому лобби, игроку не уйдёт.
